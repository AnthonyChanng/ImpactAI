# Bounded model improvement experiment

Declared before running this search. Objective: improve probabilistic forecasts, measured primarily
by log loss, with ROC-AUC/Brier/calibration reported. No target accuracy is promised; search stops
after this declared candidate set and a diagnostic confirmation pass. More iterations cannot
manufacture information absent from the source data.

The original historical test partition is excluded from experiment features, fitting, search,
calibration, confirmation, and model ranking. It has already been inspected in the original work.
Previously inspected validation data is development data; even the confirmation segment below
is not a new independent holdout. Fresh later authorized matches are needed for such a claim.

## Search and selection

1. Use timestamp-aligned 60%/80% boundaries of training series for two expanding-window folds:
   earliest 60% → next 20%, then earliest 80% → final 20%. No series or shared timestamp is split.
2. Screen the declared feature/parameter combinations by mean fold log loss, training every
   transformer and historical lookup on only the earlier part of each fold.
3. Refit the top four candidates plus the original selected XGBoost specification on all original
   training series. Select minimum uncalibrated log loss on the first chronological half of
   validation (approximately 480 series, boundary aligned to timestamps).
4. Fit scalar temperature on the next half of remaining validation timestamps. Freeze selection
   and calibration, then score the last segment once for diagnostic confirmation. Compare with
   the original specification calibrated on exactly the same calibration segment.
5. Report paired series-bootstrap log-loss differences, map slices, full search results, negative
   results, and feature provenance. Do not adapt the candidate set using confirmation results.

## Candidate families

Round feature sets: original, preceding-round windows/streak/half score, past-training team ratings,
and their combination. Ratings use only completed reliable training games from strictly earlier
timestamps. Maps in a series update ratings together; simultaneous series cannot see each other.
Validation uses frozen end-of-training ratings. Raw team/player IDs are never model inputs.
Known prior round outcomes remain available within each validation game, as in the original model.
Economy fields with unverified timing remain excluded.

Player feature sets: original, original plus training-only standardized contextual components,
and original plus observed ACS/multi-kill rate. These are retrospective association experiments;
no team/opponent scoreboard totals or identity features enter primary candidates. The contextual
heuristic index is not changed or relabeled as a learned causal impact score.

Six fixed XGBoost specifications per feature set: the existing selected specification; 600 trees
at depth 3 / rate .035 / child weight 30 / lambda 10; 500 at depth 5 / .03 / 50 / 10;
400 at depth 7 / .04 / 50 / 10; 500 at depth 4 / .035 / 100 / 25; and 600 at depth 6 /
.025 / 40 / 10 with row sampling .85 and column sampling .9. Other settings stay deterministic
with seed 42. The original specification is 180 trees / .05 / 30 / 5, depth 5 for rounds and
depth 3 for players. Total: 24 round and 18 player configurations, each screened in two folds.

Models are saved as separate research candidates, not activated automatically in the dashboard.
Historical feature inference requires the accompanying lookup state and preceding-round inputs.

Method references: [XGBoost parameters](https://xgboost.readthedocs.io/en/stable/parameter.html)
and [selection bias in nested validation](https://scikit-learn.org/stable/auto_examples/model_selection/plot_nested_cross_validation_iris.html).
