# Postgame player research protocol — October 16, 2026

The user prioritized postgame player analysis and authorized continued local training. This run has two separate objectives: improve individual-statistic association with team outcomes, and improve outcome-free expected-statistic benchmarks for comparable players. Neither objective establishes causal individual impact.

## Data and stopping rules

- Use only the supplied historical professional matches. Keep the original MatchID partitions. Exclude original test rows from all new fits, predictions, and model selection.
- Screen on three expanding temporal folds within original training: earliest 50% → next approximately 17%, earliest 67% → next 16%, earliest 83% → remaining 17%. Whole timestamps and series remain together.
- Preserve the previous validation subdivisions: 480 series for selection, 238 for temperature calibration, 243 for a final diagnostic comparison. These subdivisions were inspected previously; **none is a fresh independent test**.
- Complete this declared search once; do not keep adapting to its final diagnostic scores. Retain failures and negative results. If gains plateau, report that rather than endlessly fitting the same data.
- Four threads, existing local Python dependencies, no cloud services or new datasets.

## Association model

Reference: the prior research winner, `context__subsampled` (600 trees, depth 6, learning rate .025). Also retain the application's original specification for comparison.

Screen 12 new candidates: three feature sets (`context`, `expanded`, `expanded_context`) × four recipes (shallow/medium/deep/strongly regularized). Recipes cap training at 1,400–2,400 trees. For each fold, use the last 15% of its training series for early stopping, fit preprocessing and context references only on the earlier 85%, then refit on the entire fold training period with the chosen tree count. The outer fold's labels never determine tree count. Refit the top three candidates plus the prior winner on original training, using the same inner procedure.

Expanded features use only the selected player's postgame record: detailed multi-kill rates, separate plants/defuses, one-versus-one and multi-opponent clutch counts per round, ACS, exact match length, net openings, and opening involvement/success. A clutch count is not a clutch success percentage; attempt counts are unavailable. No other-nine-player scoreboard, team/player IDs, final team scores, winner, KAST, or unverified economy features enter the design matrix. Algebraically related additions are assessed together against the existing compact feature set, not interpreted as independent causal effects.

Compare individual finalists, a three-seed average of the best single candidate, and an equal-probability average of the top three new finalists on the selection segment. Freeze membership and weights before temperature fitting and diagnostic comparison. Do not tune ensemble weights against the final comparison. Report aggregate metrics, series-bootstrap differences, map/agent/patch/match-length slices, and training-known versus unseen player IDs (IDs are evaluation grouping only).

## Outcome-free peer benchmarks

Predict six component means (combat, openings, damage, assists, objectives, clutches) using agent, map, patch, and match length only. Compare the existing hierarchical smoothed means with two boosted-regression recipes, plus a global-mean diagnostic. Fit all target scaling and reference statistics within each training fold. Select by average squared error divided by training component variance. Evaluate on the same development partitions, reporting each component separately. Better expected-statistic estimates do not themselves validate a composite impact score or percentile distribution; this run will not invent a new validated impact label.
